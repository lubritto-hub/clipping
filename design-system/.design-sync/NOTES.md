# design-sync notes — @terra-carbon/design-system

Repo-specific gotchas for future syncs. Read before touching config.

## Layout

- The DS package is `design-system/`, not the repo root (the repo root holds an
  unrelated Python news-clipping script). **Run every converter command with
  `design-system/` as the cwd** — `.design-sync/` lives there, and
  `package-build.mjs` resolves `.design-sync/overrides` relative to cwd.
- Staged scripts live at the **repo root** `.ds-sync/`, so commands read
  `node ../.ds-sync/<script>.mjs`.

## Build

- `npm run build` runs esbuild (ESM bundle, react external) then
  `tsc --emitDeclarationOnly` for the `.d.ts` tree, then concatenates
  `src/styles/{tokens,components}.css` into `dist/styles.css` and copies
  `dist/tokens.css`. It is one-shot — no watcher, no early exit.
- `dist/` is gitignored; run the build before the converter on a fresh clone.

## Headless browser (this environment)

- The environment ships chromium build **1194** at `/opt/pw-browsers`, but the
  installed playwright expects **1234**, so `chromium.launch()` fails with
  "Executable doesn't exist". Workaround in use: a symlink farm at
  `/home/user/.pw-shim` mapping the expected `chromium_headless_shell-1234` /
  `chromium-1234` paths onto the real 1194 binaries, then
  `PLAYWRIGHT_BROWSERS_PATH=/home/user/.pw-shim` on every validate/capture run.
  On a machine with a matching playwright, drop the env var.

## Theming — the one that bites

- **Theme tokens must be selected on `[data-theme="dark"]`, not
  `:root[data-theme="dark"]`.** `TerraCarbonProvider` renders a `div`, not the
  `<html>` element, so a `:root`-scoped selector silently never matches and the
  dark register renders with light-theme values. `tokens.css` is therefore
  structured as: theme-independent values on `:root`; light colours on
  `:root, [data-theme="light"]`; dark colours on `[data-theme="dark"]`; and the
  dark block repeated under
  `@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) }`.
  The last three blocks are **generated by a script from one source block** —
  if you hand-edit one, re-run the duplication or they drift.

## Fonts

- Satoshi (brand face), Inter and JetBrains Mono are declared in
  `cfg.runtimeFontPrefixes` — they are deliberately **not bundled**. The host
  app serves them if it wants them; otherwise the stack falls to the system
  grotesque. This suppresses `[FONT_MISSING]`; do not "fix" it by shipping
  webfonts without checking licensing first.

## Card layout

- Ten components are pinned to `cardMode: "column"` in `cfg.overrides` because
  their stories render wider than a grid cell (`[GRID_OVERFLOW]`): Glass,
  Heading, Pagination, ProgressBar, RadioGroup, Stack, Stat, Table,
  TerraCarbonProvider, Tooltip. Modal uses `cardMode: "single"` at 720x520.
- `Modal` needs `contained` in previews so its backdrop stays inside the card
  instead of covering the viewport. `Tooltip` needs `open` to render statically.
- `Glass` carries `flex: none` in CSS — without it a sized orb shrinks on the
  cross axis inside a flex row and renders as a capsule instead of a sphere.

## Re-sync risks

- **Upload never happened.** The first sync built and verified everything
  locally but could not upload: `DesignSync` had no design-system authorization
  in the remote session. There is therefore **no `projectId` in config.json and
  no uploaded `_ds_sync.json` anchor** — the next sync is still a first sync and
  will re-verify all 22 components. Grades in `.design-sync/.cache/review/` are
  gitignored working state and will not survive a fresh clone.
- The conventions header (`.design-sync/conventions.md`) names 35 tokens, 27
  props and 11 components. All verified against the build at authoring time.
  **Re-run that check on every sync** — renaming a token silently makes the
  header lie, and the design agent trusts it.
- The generated theme blocks in `tokens.css` (see Theming above) are the most
  fragile thing here: a hand-edit that touches only one block ships a light/dark
  mismatch that no test catches.
- Toolchain assumed: node 22, npm, esbuild 0.24, typescript 5.6. No network
  fetches at build time.
